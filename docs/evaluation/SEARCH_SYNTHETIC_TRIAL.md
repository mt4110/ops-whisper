# SR-02：合成ログでの検索・根拠保持・マスキング比較

実施日：2026-10-08。利用者の指定により、実ログ取得を前提とせず、全て架空の資料で検証した。業務委託の資料、Cloudflare、外部サービス、認証アカウントへアクセスしていない。範囲は固定した一ログ形式・一つの問いと、その問いに関係する失敗例。検索本体や検出器の変更は行っていない。

**合成比較は完了。用途を限定して現コマンドを保持し、解析基盤・キャッシュへ拡張しない。** 問いを絞ると指定の根拠と位置を保持できる。ただし、先頭の抜粋は代表標本ではなく、短い結果だけでは結論を出せない。狭い検索では既存rgのテキストよりJSONが大きくなる。全文に対する明示マスキング、集計と省略状態、機械可読の位置情報が必要な場合に限って使う。

## 問いと、事前に定めた根拠

問いは「demo-42に障害・再試行・復旧の記録があり、マスキング後もそれらを対応付けられるか」。障害の根本原因、サービス全体の停止、実利用者への影響まで断定する問いにはしない。

| 原文行 | 内容 | 残す判断材料 |
| --- | --- | --- |
| 3〜302 | 正常なヘルスチェック300行 | 大量の正常記録に後半の重要記録が埋もれる構成 |
| 303 | attempt=1、status=503 | 時刻、サービス・ホスト、request、event_id、試行・状態・エラー表記 |
| 305 | attempt=2、status=503 | 同じrequestに対する再試行の観測 |
| 307 | attempt=3、status=200、result=recovered | 同じrequestに対する復旧の観測 |
| 315 | 305と同一の再収集行 | 同じevent_id・試行・時刻を再収集した重複。別の失敗要求とは数えない |
| 304、306 | 架空Bearerとpassword | 根拠の周辺行にある秘密値を伏せる |
| 308 | operator_codeの架空秘密値 | 組み込みの対象外。明示ルールで追加するケース |
| 309 | token=5という非秘密のレート制御カウンター | 名称だけでは秘密のtokenと区別できない負例 |
| 311〜314 | 架空の秘密鍵ブロック | BEGINを含まない313行だけの抜粋にも全体検出の範囲を反映する |

時刻順と収集行順は同じとは限らない。検索は原文順で返す。ログにエラー名が記録されていることを、原因の独立した検証と混同しない。

## 条件と測定方法

各条件で、同じ一ファイル・リテラル文字列・大文字小文字の区別・周辺行数を使い、次を実行する。

1. `rg --json`で原文位置・全一致行・出現数を確認する。
2. rgのファイル名・行番号付きテキストを、全一致を返す比較出力として測る。
3. ops-whisperの通常JSONと、マスク付きJSONを同じ表示上限で測る。
4. 期待結果に対して全件数、省略数、根拠位置、必要項目、秘密候補と非秘密のカウンターの保持／欠落を照合する。終了後に原文SHA-256の不変を確認する。

広い検索は`service=demo-api`、周辺0行、優先5一致、全体3000文字。要求の検索は`request=demo-42 attempt=`、周辺1行、優先10一致、全体6000文字。カウンターと鍵途中の検索は周辺0行、優先5一致、全体3000文字。全て一行抜粋上限は既定の400文字、CLI期限5秒。原文が短いため今回は行の途中切り出しは発生していない。

文字数はUnicodeコードポイント、バイト数はUTF-8。今回はASCIIのみで両者は同じ。rgはテキスト、ops-whisperは追加のメタデータ付きJSONであり、同じ表示形式の比較ではない。マスク付きJSONのrootはこのチェックアウトの絶対パスを含むため、別のパスで実行すると文字数が変わる。トークン、費用、速度、ピークメモリ、導入・レビュー時間は測っていない。

## 判断と、ここで終了する範囲

- **返却を小さくするだけなら、まず既存rgの検索条件を絞る。** この例では狭い検索のrg出力1383文字に対しマスクJSONは2894文字。JSONへ変換すれば常に安くなるという前提は成立しない。
- **省略を認識し、問いに沿って再検索する。** 広い検索の先頭5行だけでは障害・復旧の結論を出せない。要求IDへ絞ることで必要な観測4行を回収できた。代表性・関連度順位を保証する新機能の根拠にはしない。
- **マスキングは資料の項目の意味を含めて定義する。** 追加ルールはこの架空のoperator_codeを扱えたが、他の資料の未知秘密は保証しない。tokenという名称だけで非秘密のカウンターを伏せることもある。既知の正例・負例をルールごとに残す。
- **原文の位置が残ることと、証拠の内容が残ることを分ける。** 広すぎるルールは位置を保っても状態・関係を失う。秘密保持のために検出を自動で弱めず、項目の意味と共有範囲を定義してルールを再判断する。
- **現コマンドは限定用途で保持し、今回の比較を終了する。** 全文ルール適用、省略と件数、機械可読の出典が必要な場合に使う。実ログ提供を次工程の必須条件にせず、合成検証を何度も増やして製品価値の証拠にしない。

実案件での有用性・時間短縮・他の利用者の需要は未検証。再走査の性能負担も未計測のため、キャッシュ・SQLite AST・Git履歴・DB解析を追加する根拠は得ていない。XML・HTML・Markdownは、別の具体的な抽出目的を選ぶ候補のまま。今回の合成ログ比較で形式パーサーの実装を自動開始しない。
