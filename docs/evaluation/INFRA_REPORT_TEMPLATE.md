# インフラの稼働状態と用途を説明する調査報告の記録型

未記入のテンプレート。収集済みの資料から、観測事実と結論を対応付けて提出するために使う。新しい収集・接続・実行を許可するものではない。実案件の記入版は承認された保管場所へ置き、このリポジトリへコミットしない。

## 作業票：IR-01

対象を選ぶ段階で記入する。機密の実パスや案件名は承認された保管場所だけに記載し、公開用の記録では資料IDを使う。

| 項目 | 記入 |
| --- | --- |
| 対象の既存報告書 | 未指定 |
| 読んでよい収集済み資料と対象外 | 未指定。フォルダ全体の指定でも不要な秘密ファイルは読まない |
| 閲覧・編集を認める範囲 | 未確認。元資料を変更せず、報告の作業コピーを編集する |
| 作業版の保存先 | 未指定。既存の承認された保管場所を使う |
| 提出先が判断したいこと | 未確認。役割、観測された稼働、業務利用、廃止可否を区別 |
| 作業時間の上限と終了時点 | 未設定。到達しなかった点は未確認として残す |
| 主力の直近成果との関係 | 未確認。遅らせる必要がある場合は保留 |

対象・利用権限・作業枠が確定するまで、実案件の資料を探索しない。作業票の記入だけでIR-01の完了とは扱わず、下の問い・対象・観測期間も確認する。

## 調査の問いと範囲

| 項目 | 記入 |
| --- | --- |
| 説明したいこと | 未記入。例：どの役割を持ち、いつ利用が観測されたか |
| 対象と対象外 | 未記入。提出先に合わせた資産IDを使う |
| 観測期間とタイムゾーン | 未記入 |
| 資料の種類と収集条件 | 未記入。ログ、設定、構成資料、担当者説明を区別 |
| 取得できなかった範囲・権限の制約 | 未記入 |
| 提出先の開示条件 | 未記入。マスキングしても共有が許可されるとは限らない |

## 提出用マスキングの定義

[マスキング方針](../INFRA_REPORT_WORKFLOW.md#7-ログと提出物のマスキング方針)に沿って、対象の提出先ごとに記入する。秘密値・実名対応表はここへ記入しない。

| 項目 | 記入 |
| --- | --- |
| 共有先・共有経路・開示を認める範囲 | 未確認 |
| 対象の本文・ログ抜粋・添付・ファイル名・参照先 | 未指定 |
| 全体マスクする情報のカテゴリ | 認証秘密は全体マスク。その他は対象資料に応じて確定 |
| 別名化する識別子と有効範囲 | 未設定。本文・索引・添付を含む同じ報告一式で一貫させる |
| 実値を保持する項目と理由・開示条件 | 未設定。認証秘密の部分保持は行わない |
| 使用した編集手段・自動検出の有無 | 未指定。使った場合は版・設定・対象を記録し、原文を外部送信しない |
| 原資料・作業版・対応表の保管とアクセス・保持期間 | 未確認。組織の既存ルールに従う |
| 確認対象の版・確認担当・確認日・未解決箇所 | 未確認 |

共有条件が未確定、処理が失敗、確認できない部分がある場合は、提出版の確定を保留する。確認記録のカテゴリや位置にも秘密値を含めない。

## 資産ごとの結論と根拠

| 結論ID | 資産ID | 主張 | 観測・推定・未確認の区分 | 根拠IDと関係 | 制約・反対の証拠 |
| --- | --- | --- | --- | --- | --- |
| C-001 | R-001 | 未記入 | 未確認 | 未記入。支持・反証・制約を区別 | 未確認 |

「存在する」「起動している」「正常に応答する」「業務で使われる」は別の主張。確認した状態だけを書く。用途は、設定上の役割、観測された挙動、担当者の説明、推定を区別して記載する。推定の強さを根拠のないパーセントにしない。

一つの主張が複数の根拠を参照しても、一つの根拠が複数の主張を支持してもよい。根拠IDの存在だけで主張が正しいと扱わず、その資料が何を支持するか説明する。[記入済みの合成例](INFRA_REPORT_EXAMPLE.md)と[作業手順](../INFRA_REPORT_WORKFLOW.md)を参照。

## 根拠の索引

| 根拠ID | 種類 | 対象・時刻範囲 | 承認された原資料の参照先 | 関連する結論IDと支持・反証・制約 | この根拠だけでは分からないこと |
| --- | --- | --- | --- | --- | --- |
| E-001 | 未記入 | 未記入 | 未記入 | 未記入 | 未記入 |

原文全体を貼る代わりに、必要な箇所へ戻れる参照を残す。参照先そのものに内部パスや機密の識別子が含まれる場合は、提出版では根拠IDだけを使い、対応表を許可された環境に保つ。対応表や原資料の送信は別途許可された範囲に限定する。提出先が参照先へアクセスできない場合は、許可された抜粋・添付または資料管理者への照会方法を示す。

## 不明点と確認依頼

| 不明点 | 結論への影響 | 既存資料で確認できるか | 追加作業が必要な場合の対象・権限 |
| --- | --- | --- | --- |
| 未記入 | 未記入 | 未確認 | 未承認 |

ログに利用が見えない場合は「指定期間・資料では未観測」と書く。保存期間、ログ設定、欠損、時刻ずれ、定期実行・障害時だけの利用を確認せずに「未使用」「削除可能」と断定しない。廃止・停止の実行判断は、この報告だけで代行しない。

## 提出版の確認

- [ ] 結論の各行に、戻って確認できる根拠または「未確認」がある。
- [ ] 観測期間・対象外・不足資料を示した。
- [ ] 稼働、利用、役割、推定を混同していない。
- [ ] 別名にした資産IDが本文と根拠索引で一致する。
- [ ] 秘密値・内部情報の開示条件と、提出先の権限を確認した。
- [ ] 認証秘密の全体、再出現、複数行、本文・クエリ・エラーの値を確認した。
- [ ] 実際の提出用ファイル一式を開き直し、添付・名前・参照先も確認した。
- [ ] 同じ対象の別名が本文・索引・添付で一致し、対応表が提出版へ含まれていない。
- [ ] 意図して保持する項目の理由を記録し、未解決の秘密候補・検査失敗がない。
- [ ] 伏字で主張を検証するための情報を消していない。

## レビュー結果：IR-03

結論ごとに根拠IDから原資料の位置へ戻り、主張を支える範囲を読む。IDや参照先が存在することと、主張が支持されることは別に確認する。

| 対象の結論ID・根拠ID | 確認したこと・問題 | 報告への修正 | 未確認として残すこと・確認先 |
| --- | --- | --- | --- |
| 未記入 | 未記入 | 未記入 | 未記入 |

最終状態：未レビュー。内部レビュー済み、提出候補、保留のいずれかと理由を記入する。「提出候補」は外部提出の実施・承認を意味しない。

マスキング確認状態：未確認。確認済みの場合も、検出漏れがない保証とは扱わない。編集・添付差し替え後は確認状態を未確認へ戻す。

この型が既存の報告様式と重なるなら、既存様式の不足欄だけを補う。専用アプリや自動インフラ解析を作る根拠として扱わない。
