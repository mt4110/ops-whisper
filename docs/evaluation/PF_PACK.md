作業日：2026-10-08。対象は現在の小さなsearch CLI。追加機能、公開、commit/push、GitHub設定変更、依存インストールは含めない。

## 候補と公開の区別

公開候補は[明示ファイル一覧](publication-files.txt)にあるソース・文書・合成資料だけ。作業ツリーの一括コピーや未追跡ファイルの一括追加は行わない。`.git`、Pythonキャッシュ、実ログ、ローカルルール、対応表、作業ディレクトリ、テストの一時データは含めない。実行用Python・rgも同梱しない。

2026-10-08のGitHub API確認では、`mt4110/ops-whisper`はpublic、default branchはmain、licenseはnull、private vulnerability reportingはfalse、Actions実行履歴は0件。ローカル履歴はREADMEだけを含む`14f363d`の1コミットで、元の内容はプロジェクト名一行。今回のCLI・文書一式は未コミット。公開リポジトリが存在することを、今回のCLI公開が済んだことと同一視しない。

## 非公開報告窓口の準備

候補はGitHub Private vulnerability reporting。対象は`mt4110/ops-whisper`のこの設定だけで、公開Issueを脆弱性受付にしない。報告内容は版・OS・期待と実際の動作・合成最小再現・影響とし、実ログ・実トークン・顧客資料は不要。[SECURITY.md](../../SECURITY.md)とIssue案内は現在の無効状態を明示している。

有効化は、リポジトリ管理者がSettings → Advanced Security → Private vulnerability reportingで行う。[GitHubの公式手順](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository)に従う。設定変更の承認は未取得のため、今回は実行しない。

承認後に確認する項目は、設定APIのenabled、[Advisoriesの受付リンク](https://github.com/mt4110/ops-whisper/security/advisories)、管理者の通知設定・通知先。通知を受け取れたことの確認はメンテナーの操作が必要な場合がある。通知確認のために架空の脆弱性報告を送信しない。受付・修正期限や報奨金は約束しない。

復旧案は同じ設定を無効へ戻し、SECURITY.mdの受付状態を更新すること。無効化も今回自動実行する操作ではない。既存報告の削除や公開は含めない。

## 再現確認の方法

1. 明示一覧の通常ファイルを、Git情報・キャッシュを含まない新しい作業ディレクトリの`source`へコピーする。リンクは拒否し、実行ビットを保持する。
2. 元とコピーのSHA-256・ファイルモードを照合し、候補の一覧とハッシュ記録をソース外へ保存する。
3. `PYTHONPATH`を外し、Pythonのユーザーsiteを無効にし、bytecode保存を無効にする。候補をcwdとして実行し、importされた`ops_whisper`が候補内のファイルか確認する。
4. 既存の文書検査、52テスト、READMEのCLI例7件、6条件の合成比較を実行する。YAMLはローカルの既存Rubyで構文確認する。
5. 原文と候補の実装・fixtureが試験後も変わっていないことを確認する。合成テストが作るtempは保持し、ソース候補へ含めない。

必要条件はPython 3.11以上とPATH上のrg。別のファイル一式からの再現であり、別OS・別マシン・依存未導入の初回セットアップの試験ではない。Git履歴を移したcloneでもない。現環境のPython・rg・OSを利用する。
