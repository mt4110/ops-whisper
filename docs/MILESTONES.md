# ops-whisper マイルストーン

更新日：2026-10-08。**現在の目的は、小さな検索CLIをポートフォリオとして完成させること。** 利用者は「今の機能で十分」と判断した。独立した収益プロダクトとしての需要検証や、実案件の資料提供を、今回の完成条件にしない。

## 現行の到達目標

完成形は、**第三者が用途・使い方・設計判断・限界を理解し、合成データで再現できるローカルCLI**。既存rgで検索し、原文の位置・全一致件数・省略を残し、明示TOMLで本文をマスクしてから抜粋する。汎用解析基盤、全秘密の検出器、AIへの自動送信は目標に含めない。

「暫定」は、機能を増やし続ける意味ではない。PF-1を今回の完成地点とし、必要ならPF-2で公開候補を整え、具体的な承認後だけPF-3へ進む。公開しない場合でもPF-1でポートフォリオのローカル成果物として終了できる。

| ID | 到達したら何になるか | 達成を確かめる条件 | 現在の判定 |
| --- | --- | --- | --- |
| PF-0 | 動作する小規模CLI | 検索・位置・件数・省略・出力上限・明示マスキングが動き、主要な境界と失敗時の振る舞いを確認できる | ローカル完了。SR-01・MS-01 |
| PF-1 | 再現して説明できるポートフォリオCLI | 日英READMEから実行でき、合成の正例・負例と設計判断、既存rgとの差、未検証事項を辿れる | ローカル完了。SR-02と今回の文書整理 |
| PF-2 | 第三者が試せるOSS公開候補 | 公開対象・ライセンス・報告方針を整え、公開するソース一式だけで再現し、レビュー用一覧と検証記録を提示できる | ローカル完了。MIT採用済み・公開は別段階 |
| PF-3 | ソース公開済みのポートフォリオOSS | 承認されたソースを公開し、対象版・README・ライセンス・報告窓口・リモートCI結果の状態を確認できる | 承認済み。Linux予行成功・非公開報告有効化。通知確認待ち |

PF-0とPF-1の「完了」は、現在のチェックアウトとローカル環境での確認。別環境での初回導入やリモートCIの成功、需要・収益・時間短縮・完全な漏えい防止を意味しない。PF-3も広い採用や収益の証明ではない。

## PF-1：再現して説明できるポートフォリオCLI

- [x] [日英README](../README.md)に現在の用途・実行例・完成段階・限界を記載した。
- [x] 実ログなしで広い検索から絞った検索へ進むデモを用意した。
- [x] 固定した架空ログ、事前の期待結果、再現スクリプト、結果記録を対応付けた。
- [x] 未知の秘密、過剰マスク、抜粋からの根拠欠落、重複観測、JSONが大きくなる例を説明した。
- [x] 機能追加を止める地点と、OSS公開準備の残作業を分けた。

根拠は[合成比較の記録](evaluation/SEARCH_SYNTHETIC_TRIAL.md)と[実行タスク](TASKS.md)。デモは「短い結果から結論を急がず、省略を確認して問いを絞る」「伏字で情報を失う場合も説明する」までを示す。CLI自身が原因を分析・結論化する機能ではない。

設計を説明するときは次の判断と、その不利な面も提示する。

| 判断 | 目的 | 残る負担・限界 |
| --- | --- | --- |
| 検索には既存rgを使う | 独自検索エンジンの保守を避け、抜粋と契約へ範囲を絞る | rgの導入・版・ignoreとglobの動作へ依存する |
| 全件数と表示の省略を分ける | 抜粋を全件と誤認せず原文へ戻れるようにする | 出力が短くても対象走査は最後まで行う |
| 一致ファイルの全文でマスクする | 秘密鍵等の途中抜粋へ、全文での検出範囲を反映する | 再読み込み、サイズ上限、誤検出・検出漏れがある |
| regexを期限付きワーカーで処理する | 異常に遅いルールの処理を中断できるようにする | 子プロセス起動と資源管理が増える |
| 検査失敗時は結果本文を出さない | 不完全なマスク結果を成功した出力にしない | 利用者は入力・設定・期限等を見直す必要がある |

**この段階で今回のポートフォリオ機能開発を終了する。** 実務での便益測定、競合の再調査、新しい合成ケースの追加を終了の必須条件にしない。

## アイデアの選別と再開条件

| アイデア | 今回の採否 | 到達目標への寄与・再開条件 |
| --- | --- | --- |
| 広い検索から根拠を回収する再検索デモ | 採用・PF-1に反映 | 既存コマンドと合成fixtureで、省略の読み方を説明できる |
| 自分のソースを検索する利用例 | 採用・日英READMEに反映 | 実運用ログなしで、コードを読む補助CLIとして試せる |
| 設計判断と不利な面の対応表 | 採用・本書に反映 | 実装規模より、範囲・資源・失敗時の判断を説明できる |
| 出典付きMarkdown形式の出力 | 保留 | JSONを毎回同じ形の報告へ整形する実際の負担が残る場合に、一つの出力形式として再評価 |
| 定型ログ集計 | 保留 | 一形式・一つの問い・重複等の数え方と必要な出力が決まる場合のみ検討 |
| XML・HTML・Markdownの構造抽出 | 保留 | 行検索で答えられない具体的な構造の問いが出た場合に、一形式・一目的を選ぶ |

保留候補はPF-2/PF-3の依存にしない。再開する場合は、解く不足、既存代替、対象と完了条件、主力への影響を一件だけ定義して別途判断する。ポートフォリオを豪華にすることだけを理由に実装を再開しない。

## M4：実際の共有作業で続ける理由を確認

対応タスク：OW-12〜OW-13。成果物：M0Aと同じ種類の作業の比較記録。実ログは利用者の環境から出さず、記録には時間・操作・修正・判断だけを残す。

比較は同じ入力範囲・同じ伏せる方針・同じ完了条件で行う。ツールが作った結果を人が確認してから完了時間を計る。初回は学習時間を分離する。二回目に慣れがある場合は実行順の偏りを記録する。

観測する項目：

- 全体所要時間、繰り返し置換の操作、取りこぼしへの手動対応。
- 誤検出の修正負担と、説明に必要な情報が残ったか。
- 未検出情報を確認できたか、また使う具体的な場面があるか。
- 導入と設定の負担を含めて便益が残るか。

続ける条件は、手作業では繰り返した面倒が減り、確認負担や説明能力を損なわず、別の自然な共有機会でも使う理由があること。一回の成功から検出率や一般的な速度改善を推定しない。

終了条件は、既存手段で十分、設定・確認の手間が便益を上回る、自然な再利用がない、安全条件を満たすには大幅な追加開発が必要な場合。終了後の削除・アーカイブも対象を示した別承認に従う。
