# ops-whisper search：開発版の契約と使い方

更新日：2026-10-08。承認された最小範囲のローカル実装。検索には既存のripgrepを使い、返す本文を小さくし、元ファイルの位置と省略を残す。独自の検索エンジン・意味解析は持たない。個別承認された本文の[TOMLマスキング](MASKING.md)を追加した。

## 実行

Python 3.11以上とPATH上の`rg`が必要。Pythonの追加パッケージは不要。チェックアウト内から実行する。グローバルインストールや配布版は用意していない。

```sh
./ops-whisper search 'host=' --root examples/input.synthetic.txt --context 0
./ops-whisper search 'status=503' --root examples/input.synthetic.txt --context 0 --json
./ops-whisper search 'SearchError' --root ops_whisper --glob '*.py' --max-results 5 --max-chars 2000
./ops-whisper search --root examples/input.synthetic.txt --context 0 -- '-literal'
./ops-whisper search 'host=' --root examples/input.synthetic.txt --mask-rules examples/masking.synthetic.toml --json
./ops-whisper search --help
```

`query`は大文字小文字を区別する一行のリテラル文字列。正規表現、複数行、空文字列を受け付けない。`.*`も文字として検索する。ハイフンで始まる検索語は、オプションの後の`--`に続ける。

## 範囲

- `--root`は必須。既存の通常ファイルまたはディレクトリを指定する。指定したroot自体がシンボリックリンク、FIFO、デバイスなら拒否する。
- ディレクトリの再帰探索では、ドットで始まるファイル・ディレクトリを明示的に除外する。探索中のシンボリックリンクは辿らない。
- その他はrgの既定のignore規則を使う。Git ignoreはrgがリポジトリを認識する等の条件に従う。既存の親・グローバルignore設定も探索範囲へ影響する。
- `--glob`はrgの規則に従う。**肯定globはignoreされた通常ファイルも含め得る。** 隠しファイルの再帰除外は肯定globより後で適用する。否定globも指定できる。
- 通常ファイルをrootに明示すると、rgの再帰探索時のignore・隠しファイル除外を適用するとは限らない。ファイルを指定する前に内容を読んでよいか確認する。
- バイナリはrgの既定の検出に従う。一致ファイルでバイナリ停止が報告された場合、結果本文を全て破棄して失敗する。全入力のUTF-8・バイナリ検査ではない。一致・周辺イベントの不正UTF-8や不正なパス表現も失敗する。
- `--no-config`で`RIPGREP_CONFIG_PATH`を無効化する。前処理、圧縮展開、追従、隠しファイル全探索、任意のrg引数を渡す機能はない。

rootの祖先にあるリンク、探索中のファイル差し替え、ハードリンク、マウントを隔離するサンドボックスではない。稼働中ログの固定スナップショットでもない。取得した行番号は検索時点のファイルに対する位置であり、後でファイルが変わればずれる。

## 上限と出力

| オプション | 既定値 | 許容範囲と意味 |
| --- | --- | --- |
| `--context` | 2 | 前後0〜10行。ファイル境界を越えない |
| `--max-results` | 20 | 優先して選ぶ一致行1〜200件。出現箇所の数ではない |
| `--max-chars` | 8000 | メタデータ・改行・JSONエスケープを含む応答全体512〜64000文字 |
| `--line-chars` | 400 | 一行につき切り出す原文32〜2000文字。制御文字の可視化前の長さ |
| `--timeout` | 30秒 | rg起動後の読み取り・待機の期限。0より大きく300以下 |
| `--glob` | なし | 最大16個、各512 UTF-8バイト以下 |
| `--mask-rules` | 無効 | 明示したTOMLで一致ファイル全文へルール適用。サイズ・時間等は[別契約](MASKING.md) |
| 検索語 | 必須 | 一行、最大4096 UTF-8バイト |

出力文字数はPythonのUnicodeコードポイント数。UTF-8バイト数、画面の桁数、トークン数ではない。応答を収めるため周辺行から除き、その後は一致行を丸ごと省く。メタデータだけでも収まらなければ本文なしで失敗する。JSONを文字数で途中切断しない。

検索はパス順に行い、最初の一致行を優先する。関連度による順位付けや代表標本抽出ではない。長い一致行は最初の一致位置の近傍を切り出し、`column_start`を原文の1始まりの文字位置として記録する。長い検索語や同じ行の後方の一致まで全て載る保証はない。`clipped`が立つ行は原文に戻って確認する。

全一致件数を得るため、表示上限に達してもrgの対象を最後まで走査する。読み取り量・走査時間を小さくする機能ではない。JSONイベント一件は1 MiB以下に制限するため、非常に長い一致・周辺行は小さく表示できても取り込み時点で拒否することがある。時間上限はリアルタイムOSの厳密な停止保証ではない。

テキスト出力は範囲・集計・省略状態に続き、`> path:line:column 本文`で一致行を返す。周辺行は`>`を付けない。制御文字・双方向制御文字は可視化し、端末へそのまま出さない。これは秘密値のマスキングとは異なる。

## JSON schema_version 1

マスクありの検索語・glob値は`[WITHHELD]`を表示する。マスキングの資源制限と意味は[MASKING.md](MASKING.md)に従う。

| フィールド | 意味 |
| --- | --- |
| `scope` | 絶対root、検索語、glob、検索モード、表示上限、時間上限、探索方針 |
| `stats.matched_lines` | rgが検索できた範囲の全一致行数 |
| `stats.occurrences` | 同じ行の複数出現を含む全一致箇所数 |
| `stats.files_searched` / `files_with_matches` / `bytes_searched` | rgのsummaryに由来する走査統計。全ディスクの棚卸しではない |
| `display.selected_match_lines` | 優先対象に選んだ一致行数。文字数上限で返せないことがある |
| `display.returned_match_lines` / `omitted_match_lines` | 実際に返した一致行と、全一致行からの省略数 |
| `display.clipped_lines` | 実際に返した行のうち、原文を途中で切り出した行数 |
| `display.truncated` | 選択・切り出し・文字数上限のいずれかで表示を制限した |
| `scan_completed` | rgの対象範囲の走査が正常終了し、summaryの一致数と突合できた |
| `redacted` | 明示TOMLを適用した場合true。秘密ゼロ・共有許可の判定ではない |
| `masking` | 適用状態、builtin版、有効ルール数、全文での検査ファイル・バイト・マスク範囲・文字数 |
| `lines` | `path`、`line`、`column_start`、`match`、`text`、`clipped` |

パスはrootがディレクトリならそのrootからの相対位置、ファイルならそのファイル名。root・パス表示では元のバックスラッシュを二重にし、制御文字の可視表現と別ファイル名が衝突しないようにする。表示パスをそのままシェル引数に渡さず、可視化を戻して位置を確認する。重複した周辺行はまとめる。周辺行に別の一致行が含まれた場合、`returned_match_lines`は`--max-results`を超え得る。件数を厳密に表示上限内へ制限したい場合は`--context 0`を使う。`truncated=true`は「一致行を全て返していない」だけを意味しない。

## エラーと情報の経路

| 終了コード | 状態 |
| --- | --- |
| 0 | 検索完了、一致あり。文字数上限で本文行が全て省略されても一致があれば0 |
| 1 | 検索完了、一致なし。空の結果と統計を返す |
| 2 | 不正な入力・上限・root、メタデータの出力上限超過 |
| 3 | rg起動・探索・時間超過・文字コード・イベント・集計整合・I/Oの失敗 |
| 130 | 中断 |
| 141 | 出力先のパイプが閉じられた |

走査・検証・シリアライズが成功するまで結果をstdoutへ書かない。rgのstderrは読み捨て、CLI引数や本文をエラー診断へ転載しない。エラーは一般的な分類だけを返す。失敗・中断時は子rgを停止・回収する。stdoutへ書き始めた後の出力先エラー・中断では受信側に一部が残り得る。OSや端末からの物理消去は保証しない。

**マスク未指定では検索語・パス・一致行・周辺行に秘密値がそのまま出る。指定時もパス・未知の秘密は残り得る。** CLI引数はシェル履歴・プロセス一覧にも残り得る。秘密値を検索語にしない。マスク指定時は検索語・glob値を出力で伏せるが、CLI引数は管理外。周辺行も含め、指定ルールの対象外の値は残り得る。AI等へ渡す前に、既存の[マスキング方針](INFRA_REPORT_WORKFLOW.md#7-ログと提出物のマスキング方針)に沿って共有対象を確認する。

本実装は入力ファイルを編集せず、永続キャッシュ、対応表、出力ファイル、ネットワーク送信を作らない。端末履歴、シェルのリダイレクト、swap等は管理外。PATH上のrg・Python・OSを信頼するローカルツールであり、外部バイナリの権限を隔離しない。キャッシュ、SQLite AST、Git履歴、DB分析、定型ログ集計、OCR・形式変換、`review`コマンドは今回未実装。

## 検証と比較

```sh
python3 -m unittest discover -s tests -v
python3 scripts/check_docs.py
```

macOS、Python 3.14.7、rg 15.2.0で合成入力を使って検証。文字数上限、全件数との突合、日本語、CRLF、長い行、制御文字、ignore・glob・隠しファイル・リンク、バイナリ・不正UTF-8、設定ファイルの無効化、異常なバックエンド、期限・中断時の子プロセス回収等を対象とする。合成fixtureはシステムtemp配下の`ops-whisper-test-*`等へ作り、自動削除しない。実資料・秘密値をfixtureへ入れない。Linux用CIの定義は用意したがリモート実行は未確認。Windows非対応。

SR-01完了時の返却量の一回の合成比較（maskingメタデータ追加前）：1000行の各行を`event=0000 status=503 service=demo detail=`（連番を増加）＋`x`80個＋LFとした123000バイトのファイル。通常の`rg -n -F`で全一致を返すと126893文字。同じ語・一ファイルに対し`--context 0 --max-results 5 --max-chars 2000 --line-chars 120 --json`の応答は1730文字、全1000一致行・1000出現を集計し、5行を返し995行を省略した。返した5行は末尾を切り出している。双方ASCIIのため文字数とUTF-8バイト数は同じ。絶対パスの長さで応答サイズは変わる。

これは返却量と省略表示の確認であり、実案件で十分な証拠が選べるか、トークン・費用・速度の改善、製品需要を証明しない。その後、[SR-02の合成比較](evaluation/SEARCH_SYNTHETIC_TRIAL.md)を完了した。広い検索で根拠を取り逃す例、狭い検索ではJSONの方が大きくなる例、検出漏れ・過剰マスクを記録し、用途を限定して保持する判断をした。実ログの提供を前提にせず、この合成比較は終了する。キャッシュは同じ対象・条件の再実行負担が実測され、失効と機密保存を定義できる場合だけ次の案にする。
