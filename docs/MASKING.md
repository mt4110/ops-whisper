# 検索結果のマスキング契約とTOML

更新日：2026-10-08。開発版`search --mask-rules`の最小実装。本文に指定ルールを適用し、抜粋後に秘密の断片が残る問題を減らす。未知の秘密の全検出、匿名化、提出先の共有許可を保証しない。独立した`review`の対話・承認・別名化は未実装。

## 使い方

```sh
./ops-whisper search 'host=' --root examples/input.synthetic.txt --mask-rules examples/masking.synthetic.toml --json
```

`--mask-rules`を明示した場合だけ有効。設定の自動探索・暗黙の読み込みはしない。指定した設定が不正・アクセス不能なら、マスクなしの出力へ戻らず失敗する。未指定の検索は従来どおり原文を返す。実ルールはリポジトリ外または無視対象のprivate領域に保管し、秘密の実値をサンプルやIssueへ入れない。

## TOML schema_version 1

```toml
schema_version = 1
builtins = ["bearer", "credential_assignment", "private_key"]

[[rules]]
id = "demo-secret"
pattern = 'sample-secret'
action = "mask"
enabled = true
flags = []
```

[実行できる合成設定](../examples/masking.synthetic.toml)。保留した`review`用の[旧ルール案](../examples/rules.synthetic.toml)とは別のスキーマであり、旧設定を検索へ渡すと拒否する。

| 項目 | 契約 |
| --- | --- |
| `schema_version` | 整数1、必須。boolは不可 |
| `builtins` | 有効にする組み込みIDの配列。省略時は3種全て。空配列で組み込みだけを無効化できる |
| `rules` | 追加ルールの配列。省略可 |
| `rules.id` | 必須。ASCII英字で始まる英数字・`_`・`-`の1〜64文字。組み込みIDも含め重複不可 |
| `rules.pattern` | 必須。Python `re`のUnicode正規表現。空文字列・NULは禁止、最大1024 UTF-8バイト |
| `rules.action` | 必須、`"mask"`だけ。別名化・任意の置換文字列・キャプチャ限定置換はない |
| `rules.enabled` | bool。省略時true。falseでも構文・空文字列への一致を検証する |
| `rules.flags` | `IGNORECASE`・`MULTILINE`・`DOTALL`から選ぶ重複なし配列。省略時空配列 |

未知のキー、未知のbuiltin、型違い、重複flagは拒否する。組み込みと無効ルールを含め最大32ルール。少なくとも一つは有効であること。設定ファイルは通常ファイルだけ、最大64 KiB。最終パスのリンク・FIFO・デバイスを拒否する。個別の不正値・正規表現・TOML原文を診断へ載せない。

検索対象がゼロ件でも正規表現を事前コンパイルする。空文字列に一致するルールは拒否する。入力上で初めて発生するゼロ幅一致も、その時点で全結果を破棄する。キャプチャを持つルールも一致全体をマスクする。TOMLの単引用符文字列ではバックスラッシュがそのまま正規表現へ渡る。正規表現の意味と設定解析は、[Python 3.11のre仕様](https://docs.python.org/3.11/library/re.html)と[標準tomllib](https://docs.python.org/3.11/library/tomllib.html)を使用する。

## 組み込みルール version 1

| ID | 対象とマスク範囲 | 主な限界 |
| --- | --- | --- |
| `bearer` | 大文字小文字を区別しないBearer＋空白＋トークンの一致全体 | 空白で分割・別方式・エンコードされた認証値は対象外 |
| `credential_assignment` | password、passwd、api_key／api-key／apikey、access_token／access-token、client_secret／client-secret、token、secretというキーと、`=`または`:`による値の代入全体 | キーの省略・別名、キーと区切りの間の改行、構造的な意味解釈は対象外。非秘密の設定も伏せ得る |
| `private_key` | PRIVATE KEY、RSA、EC、DSA、OPENSSH、ENCRYPTED PRIVATE KEYのBEGIN〜対応するENDを含むブロック | その他の形式、マーカーのない断片、未知のラベルは対象外 |

代入値の引用符は、エスケープした引用符と複数行を扱う。開始した引用符や既知の秘密鍵ブロックが閉じていない場合は、ファイル末尾までマスクする。無関係な後続本文も伏せ得るため、原文を安全な環境で確認する。非引用値は空白・区切り文字等までを対象とする。これはXML・JSON等のパーサーではなく、構造を正しく再生成する保証はない。

未知のキー、裸の秘密値、個人情報、ホスト名、ファイル名は自動推測しない。自分の形式に合う追加ルールと、共有前の人による確認が必要。組み込みの実装は[masking.py](../ops_whisper/masking.py)を正本とする。

## 原文位置と処理順序

1. 明示TOMLを読み、別プロセスで正規表現を検証する。
2. rgは原文にリテラル検索を行う。一致行数・出現数・位置は原文の統計として維持する。
3. rgが報告した一致ファイルを上限付きで全文読み取りし、全文でマスク範囲を検出する。抜粋にBEGINが出なくても、既知の複数行ブロックの範囲を引き継ぐ。
4. Python `re.finditer`の各ルールの一致全体を集め、ルール間の重複・隣接範囲を合成する。優先順位で別ルールのマスクを弱めない。各ルール自体の一致はPythonの非重複走査に従う。
5. CR・LFを残し、範囲内のその他の各Unicodeコードポイントを`*`へ置き換える。文字数・行番号・原文上の列位置を保った本文から抜粋し、既存の出力上限を適用する。
6. 観測したrg行を全文の原文行と照合する。追加読み取りの前後、およびそのファイルのrg終了時のサイズ・inode・時刻等に違いがあれば本文を返さない。

元ファイルへ書かず、マスクした全文や対応表をディスクへ保存しない。処理中は原文とマスク本文をメモリに持つ。文字位置はUnicodeコードポイント基準であり、UTF-8バイト位置や表示桁の保存ではない。マスクにより値の長さ・改行・出現位置が分かるため匿名化とは扱わない。

サイズ・mtime等と観測した行の照合は、OS全体の固定スナップショットや、悪意ある並行変更への完全防御ではない。稼働中ファイルは変化により失敗し得る。マーカーや前後の文脈に依存する解析には、読み取り権限のある安定した収集済みコピーを使う。非一致ファイルは追加の全文読み取り・マスク検査をしない。取得範囲全体の秘密監査ではない。

## 出力の意味

- マスクありでは検索語とglob値を`[WITHHELD]`にする。検索は元の値で行う。履歴・プロセス一覧のCLI引数まで隠す機能ではない。
- root・ファイルパスは出典として表示し、マスクしない。秘密を含む名前のファイルをそのまま共有しない。
- `redacted:true`と`masking.applied:true`は、有効な指定ルールを適用した記録。秘密ゼロ、全件検出、外部送信の許可を意味しない。ゼロ一致でも有効な設定ならtrueとなる。
- `masking`はbuiltin版、対象`matched_file_text`、有効ルール数、検査したファイル・原文バイト数、合成した範囲数、伏せた文字数を記録する。範囲数・文字数は返した抜粋だけでなく、検査した一致ファイル全文の合計。
- 原文上の一致数・出現位置・ファイル名から情報を推測できる可能性がある。伏字後の本文には検索語が見えない場合もある。

## 資源上限と失敗

一致ファイルの追加読み取りは一ファイル4 MiB、全一致ファイル合計16 MiB。UTF-8として全文を解釈し、NUL・不正バイトは抜粋外にあっても拒否する。正規表現による候補は、重複を合成する前の各一致を一ファイル10000個まで。これは実用性の合格基準ではなく、初版の資源制限。大規模ログをそのまま全形式解析するための上限ではない。

正規表現は`python -I`の子プロセスで実行し、原文とルールはstdinで渡す。argvへ秘密本文を載せず、stdoutは位置範囲のみ、stderrは破棄する。一度の正規表現ワーカーに最大2秒、設定検証・検索・追加読み取り・マスクには全体の`--timeout`を適用する。`communicate(timeout=...)`の期限超過後は明示的に子を停止・回収する。[Pythonの子プロセス仕様](https://docs.python.org/3.11/library/subprocess.html#subprocess.Popen.communicate)

ワーカーは一つの事前検証と一致ファイルごとに起動する。小さいファイルが多数ある場合は起動費用が増える。スレッドを止めるだけの実装にはしない。OSファイルI/O、プロセス起動、停止・回収の遅延まで厳密な実時間上限を保証するものではない。ワーカーのOS権限を隔離するサンドボックスではない。

不正TOML・ルール・正規表現は終了2。アクセス・サイズ・文字コード・入力変化・候補超過・期限・ワーカーの失敗は終了3。走査・マスキング完了前の失敗ではstdoutを空にする。Ctrl-Cは子を回収して130。出力を書き始めた後のパイプ・I/O障害では受信側に一部が残り得る。原文への自動フォールバックはない。
